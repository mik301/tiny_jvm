#  Java Card CAP files address API classes and methods by NUMERIC TOKEN, not by
#  name. The token assignment lives in the export files (*.exp) that ship with
#  a Java Card SDK, so it is a property of YOUR toolchain, not of this VM.
#
#  The table below is the assignment used by the bundled CapBuilder tool, so
#  jcvm and CapBuilder always agree. It is a plausible layout, but it is NOT
#  guaranteed to match the export files of the SDK that converted your CAP.
#
#  If a real CAP fails with "no token table entry for ...", dump the tokens
#  from your SDK export files (exp2text / the Converter's -exportmap output)
#  and correct the numbers here. Nothing else in the VM needs to change.
#
#  Format:
#    PKG   <package.name> <AID hex> [major] [minor]
#    CLASS <classToken> <internal/class/Name> [SIZE <cells>]
#    V     <virtualToken> <name(descriptor)ret>
#    S     <staticToken>  <name(descriptor)ret>
#
#  SIZE is the number of 16 bit instance cells the class contributes to a
#  subclass. Applet has no instance fields, so applet field tokens start at 0.
# ---------------------------------------------------------------------------
